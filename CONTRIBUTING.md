# CONTRIBUTING.md — rules for working on UTriage

Read `PROGRESS.md` at the start of every session.

## How to work
- Execute **only the phase you are asked for**. Stop at its gate and report: what was built, test results, and which gate criteria pass or fail.
- Each phase must be **intact**: at the end of a phase the repo installs, every test passes, and the CLI runs. No half-finished modules and no TODO stubs in code from earlier phases.
- At the end of every phase: update `PROGRESS.md` (Done / In progress / Open questions / Assumptions), commit, and tag `phase-N`.
- Small, readable code. Type hints and docstrings on public functions. Prefer clarity over cleverness. Every line must be easy to study.
- Before writing an algorithm, write its maths and physics in `docs/study/NN-*.md` in plain language with the equations.

## Safety design (non-negotiable)
- The rules engine stays in charge. **ML can only add flags, never remove a rules flag.** Keep a property-based test that enforces this.
- UTriage **never accepts or passes a part**. Every accept or reject decision belongs to the certified inspector.
- Advisory and offline only. No connection to UT machine controllers, PLCs, or any plant network.

## Honesty rules (non-negotiable)
- **Never invent physical constants, acceptance limits, standards content, results or citations.** Unknown values are `null` or a placeholder with `source: "UNVERIFIED — Ruri to check"`. Never reproduce tables from paywalled standards (AMS-STD-2154, ASTM E2375) from memory.
- Every number in `README.md`, the resume bullets or the docs must be generated by code into `results/*.json`. Never type a result by hand.
- Anything from the simulator is labelled **"Synthetic data"** in plots, tables and reports. Real-data results (ML-NDT) are labelled separately, with their limitations: a weld, only 3 physical cracks.
- Never claim plant validation, MIDHANI data, qualification or deployment that has not happened.
- Cite prior art (US 9,927,404 B2; Virkkunen et al. arXiv:1903.11399). Do not redistribute the ML-NDT data. Fetch it with the script and respect its LGPL-3.0 licence.

## Environment
- Target machine: i5-1135G7, 8 GB RAM, no GPU. PyTorch CPU. Stream data with `np.memmap` and never load the full dataset into RAM.
- Phase 3 training should finish in under 2 hours on the laptop. Other experiments should take under 60 minutes.
- Python 3.11+. Allowed dependencies: numpy, scipy, pandas, torch (CPU), scikit-learn, pydantic v2, pyyaml, typer, matplotlib, streamlit, pytest, hypothesis, ruff. Anything else needs an ADR in `docs/decisions/`.
- Fixed random seeds in all experiments. The app must run fully offline.
