# 0016. Titanium mode (UTriage-Ti) with structured grain noise and zone-wise reference calibration

- Status: Proposed
- Date: 2026-11-07

## Context

In automated immersion ultrasonic testing (UT) of aerospace rotating round bars and billets, titanium alloys exhibit coarse microstructural grain noise and macrozones (spatially correlated regions of similarly oriented crystallographic grains). Acoustic scattering from macrozones creates heterogeneous background noise fields that complicate flaw detection.

UTriage targets an AMS 2631-style billet and bar inspection workflow for titanium alloys. Real titanium plant data is not available to the project; public benchmark ML-NDT (316L stainless steel weld, 3 cracks) remains the only real-data evidence in the repository. All titanium scan data, signals, and evaluation metrics in UTriage are generated through simulation and are designated as **Synthetic data**.

To evaluate indication triage under titanium-like acoustic conditions, the repository requires a dedicated titanium mode (UTriage-Ti) combining structured grain noise simulation with zone-wise reference calibration.

## Decision

Adopt a titanium inspection mode (UTriage-Ti) defined by the following architectural choices:

1. **Titanium simulator mode with structured grain noise (Synthetic data)**:
   - The bar simulator introduces structured grain noise to represent microstructural scattering in titanium.
   - Noise amplitude is modulated by a lognormal spatial strength multiplier field $m = \exp(s \cdot g - s^2 / 2)$ with mean 1 ($\mathbb{E}[m] = 1$), where $g$ is a standard Gaussian random field and $s$ is the log-amplitude standard deviation parameter (`field_sigma: 0.1`, placeholder, UNVERIFIED - Ruri to check).
   - Spatial correlation of $g$ follows a Gaussian covariance kernel with axial correlation length `corr_axial_mm: 6.0` (placeholder, UNVERIFIED - Ruri to check) and angular correlation length `corr_angle_deg: 15.0` (placeholder, UNVERIFIED - Ruri to check) with periodic wrap around the 360-degree cylindrical circumference.
   - Depth-dependent relative noise levels (`zone_levels: [1.0, 1.2, 1.1]`, placeholder, UNVERIFIED - Ruri to check) are assigned across radial depth zones (`zone_edges_mm: [2.0, 12.0, 22.0, 36.0]`, placeholder, UNVERIFIED - Ruri to check).
   - All outputs generated by this mode are labelled **Synthetic data**.

2. **Zone-wise reference calibration**:
   - Reference calibration is performed on a simulated reference block containing one flat-bottom hole (FBH) per depth zone (`ref_fbh_mm: 0.8`, placeholder, UNVERIFIED - Ruri to check).
   - Each depth zone is calibrated independently to determine its reference response and noise characteristics rather than assuming uniform acoustic response across all depths.

3. **Zone signal-to-noise ratio (SNR)**:
   - Zone SNR is calculated using the formula:
     $$\text{SNR} = \frac{A - B}{C - B}$$
   - $A$ is the signal response, defined as the mean of the $3 \times 3$ C-scan pixels centred on the reference hole peak (`signal_window_px: 1`, so N = 1, placeholder, UNVERIFIED - Ruri to check).
   - $B$ is the mean noise floor in the zone's noise region, excluding pixels within `noise_exclude_px: 6` (placeholder, UNVERIFIED - Ruri to check) of the reference hole.
   - $C$ is the peak noise envelope in the zone's noise region.
   - Prior art note: This mathematical form is published in patents US 6,370,956 and US 6,401,537 (titanium ultrasonic noise); whether a given specification uses exactly this form is UNVERIFIED - Ruri to check.

4. **Alarm level and inspectability gate**:
   - The alarm candidate level is given by:
     $$\text{Alarm} = \min\bigl(C \times (1 + \text{noise\_margin}),\; \text{cap\_fraction} \times A\bigr)$$
   - `noise_margin: 0.10` is a placeholder (UNVERIFIED - Ruri to check).
   - `cap_fraction: 0.70` is a placeholder taken from a secondary-source snippet attributed to ASTM E2375 that was not read in the original - UNVERIFIED - Ruri to check.
   - Inspectability gate: A zone whose alarm level is not above its peak noise level $C$, or whose SNR is below `min_snr: 2.0` (placeholder, UNVERIFIED - Ruri to check), is flagged 'not inspectable at this sensitivity' for the human inspector. The zone is never silently passed.

5. **Safety rules and rules engine primacy**:
   - The rules engine stays in charge. Zone alarms are rules flags.
   - Machine learning models act strictly in an advisory role and can only add candidate flags; ML can never clear or suppress a rules flag.
   - Final disposition decisions rest solely with the human inspector; UTriage never issues an accept or pass decision.

6. **Calibration traceability**:
   - The inspection report records the calibration identifier and configuration hash (`id` and `hash`) that generated each zone alarm.
   - This maintains traceability between reference block settings and inspection flags.

7. **Air-gapped packaging and integrity**:
   - Model files are checked against cryptographic SHA-256 hashes prior to loading.
   - Packaged as an offline wheel bundle accompanied by root `SHA256SUMS`.
   - Zero network calls: no telemetry, background sockets, or external network requests.
   - Nuitka standalone compilation (ADR 0007) stays separate and Proposed.

## Alternatives Considered

- **Single global threshold across the entire bar**:
  Rejected because macrozones and depth-dependent beam attenuation produce non-uniform noise fields; a single global threshold is either desensitized in quiet zones or overwhelmed by false alarms in high-noise regions.
- **Fitting scattering parameters to physical alloy samples**:
  Rejected because the project lacks access to physical titanium alloy specimens or plant UT scan data; all titanium simulator parameters remain synthetic model choices.
- **Permitting ML models to override zone alarm flags**:
  Rejected because safety principles require that conventional rules-engine zone calibrations remain the non-negotiable baseline.

## Consequences and Limits

- All titanium numbers are synthetic; all scan outputs and derived metrics are labelled **Synthetic data**.
- The noise model is a simulator model choice, not fitted to any physical alloy (literature: Margetan, Thompson and co-workers at Iowa State on titanium grain noise and the noise figure-of-merit - cite as 'Iowa State QNDE grain-noise papers, exact references UNVERIFIED - Ruri to check').
- No claim of AMS 2631 conformance, formal shop-floor approval, or plant use.
- Values from `configs/ti_mode.yaml` are placeholders and every text that mentions them states: placeholder, UNVERIFIED - Ruri to check.

> **Change note (after the first calibration run, before any experiment result):** the defaults were first `field_sigma: 0.4`, `zone_levels: [1.0, 1.6, 1.3]` and `signal_window_px: 3`. On the simulated reference block the 3x3 mean cut the reference response to about a third (the simulator grid, 1 mm x 3 deg, is coarser than the beam), and with field_sigma >= 0.15 the hottest noise patch set the zone peak noise so high that no zone was inspectable. The defaults were changed to `field_sigma: 0.1`, `zone_levels: [1.0, 1.2, 1.1]`, `signal_window_px: 1`. These are simulator model choices, not measured values; `experiments/run_ti_zones.py` sweeps field_sigma so the loss of inspectability is reported, not hidden.
